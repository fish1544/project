# 时迹 · 时间记录（time-trace）

一个纯前端的时间记录应用：把一天 24 小时按分类切段记录，看**已记录 / 未记录 / 今日剩余**三条概要，用环形 / 门形 / 双环三种图看时间去向，附带目标、习惯、统计、主题与本地备份。

零依赖、零构建，双击 `index.html` 就能用；数据只存在浏览器本机（`localStorage`），不出设备。

---

## 运行

- 直接双击 `index.html`（Chrome / Edge）。
- 想在手机尺寸下预览：`python -m http.server 8123 --directory .`，然后打开 `http://127.0.0.1:8123/index.html`。

## 目录

```
time-trace/
├── index.html          入口（按序引入 6 个脚本，无内联逻辑）
├── css/style.css       全站样式（:root 配色变量，设计基准 390×844）
├── js/core.js          纯函数层：日期、区间、格式化、转义、记忆化、防抖（window.TJCore）
├── js/store.js         状态层：默认态、脏数据清洗、索引、选择器、动作、持久化（window.TJ）
├── js/icons.js         内联 SVG 图标库（window.ICONS）
├── js/charts.js        环形 / 门形 / 双环 / 折线 SVG 生成（window.CHART）
├── js/screens.js       各页面 HTML 生成器（window.VIEWS，无副作用）
├── js/app.js           控制层：路由与节点回收、绑定表 / 动作表、弹层、分钟心跳、导出
├── tests/verify.mjs    CDP 无头验收：控制台报错 + 布局 + 24 屏截图 + 图表三形态 + DOM 有界
├── tests/flows.mjs     CDP 端到端 + 内部逻辑断言（59 项）
└── README.md
```

分层原则：`core` 不碰 DOM、不碰存储；`store` 只读写状态并广播 revision；`screens` 只做「状态 → HTML 字符串」；`app` 负责绑定事件、路由、弹层与副作用。改逻辑找 `core` / `store`，改界面找 `screens` / `style.css`。

## 数据与口径

- 存储键 `time-trace:v2`，落盘结构 `{ schema: 2, savedAt, data }`；读取时逐字段校验，坏记录丢弃、坏分类回落「其他」、非法主题回落默认色、重复 id 重新分配。
- 记录模型 `{ id, date, cat, start, end, note, important }`，`start` / `end` 为日内分钟，跨零点时 `end > 1440`。
- 汇总口径：`未记录 = 已过分钟 − 已记录`、`今日剩余 = 1440 − 当前分钟`、百分比以 1440 为分母。
- 分类默认 睡觉 / 工作 / 学习 / 吃饭 / 运动 / 休息 / 其他 = `#72B7D2 / #F29374 / #F7D77C / #69DAC2 / #EC7C88 / #83AADD / #C3C3C4`，主题色默认 `#72b7d2`，另有 16 色主题池。

## 取舍说明

- 空数据状态下图表会画出「未记录」整圈 + 刻度 + 24 小时数字，与有数据时的色环形态一致，只是没有分类弧。
- 习惯与「我的」宫格使用同语义 emoji + 圆底配色呈现，没有做逐像素插画重绘。
- 「日程」「年视图」「夜间睡眠统计」为常规形态实现，未做动画级细节复刻。
- 需要系统能力的入口（数据同步、密码保护、宝盒等）点击后给出「当前版本暂未实现」提示，不假装成功。

## 测试

```bash
python -m http.server 8125 --directory .     # 另开一个终端
# 下面两个脚本默认连 http://127.0.0.1:8123/index.html，可用环境变量覆盖
$env:BASE_URL = "http://127.0.0.1:8125/index.html"
node tests/verify.mjs    # 报错 / 溢出 / 24 屏截图 / 图表三形态 / DOM 有界
node tests/flows.mjs     # 59 项：录入·计时·目标·习惯·主题·统计·图表 + 转义·持久化·revision·脏数据自愈
```

两个脚本都用 Chrome DevTools Protocol 驱动无头 Chrome（`CDP_PORT` 可改端口），不引入 Playwright 等额外依赖。最近一次结果：`errors: []`、`overflowX false`、`390×844`、图表三形态正常、DOM 常驻 3 屏；交互 **59/59 全部通过**。
