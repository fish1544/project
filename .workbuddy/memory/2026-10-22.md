# 2026-10-22 工作日志

## 星陨幸存者：补齐缺失的碰撞（commit 353dd1e）

用户反馈「部分场景未实现碰撞」。配置层面（collision_layer/mask/CollisionShape2D）全部齐全，
于是写了量化诊断脚本 `scenes/test/collision_audit.tscn` 实测，定位到真正缺失的部分：

- **根因：敌人之间完全没有碰撞**。玩家/敌人/弹丸 vs 障碍都正常，但尸潮会完全重叠——
  实测 8 个敌人挤一起最小间距 **0.59**，视觉上就是"一个敌人"。
- 修法：新增空间网格软分离（`EnemyBase._separation_push`），按重叠深度施加柔和推开速度，
  不做硬碰撞（硬碰撞会把尸潮挤成一堵墙）。间距恢复到 **16.8**。
- 性能：全量重算 140 敌人 = 2.34ms/帧（占 16.7ms 预算 13%）。
  改为 3 帧降频 + `_ready` 里按 instance_id%3 错开相位 → 每帧只有 1/3 敌人重算，峰值 ~0.8ms。

### 坑

- GDScript：`Dictionary.get()` 返回 Nil，**不能**赋给 `var x: Array`（运行时报错），
  要先 `var b = _grid.get(k)` 再判空。遍历无类型 Array 时 `b.global_position` 是 Variant，
  `var d := p - b.global_position` 会推断失败，需显式声明中间变量类型。
- 写审计脚本等帧时：`_update_props` 跑在 `_process`，只 await `physics_frame` 不会推进，
  必须同时 await `process_frame`，否则统计到 0 个障碍。
- Node 基类没有 `get_viewport_rect()`（那是 Viewport/Window 的方法），Node 里要用
  `get_viewport().get_visible_rect()`。
- 测玩家是否被障碍挡住时，直接设 `player.velocity` 无效（会被 `_physics_process` 里的
  `Input.get_vector` 覆盖），要用 `Input.action_press()` 模拟真实按键。
